# Phase 10 — 맵 에디터 세부 계획 (v1.1)

Phase 9에서 만든 것들 — docking ImGui, Inspector, 렌더러/ECS 경계 — 이
전부 이 단계의 재료다. 이 문서는 ROADMAP Phase 10 항목을 **커밋 단위로
쪼갠 실행 계획**이다. 계획 문서이므로 코드는 없고, 설계 결정과 검증
방법만 담는다.

---

## 1. 현재 상태 진단

Phase 9 종료(v1.0) 시점 코드의 한계. 각 항목이 세부 단계 하나와 대응된다.

| # | 문제 | 증상 | 해결 단계 |
|---|------|------|-----------|
| 1 | 씬이 스왑체인(백버퍼)에만 그려짐 | 에디터 창 "안에" 씬을 넣을 수 없음. 패널이 씬을 가림 | 10.1 |
| 2 | 종횡비가 스왑체인 크기에 묶임 | 뷰포트 창 크기 ≠ 창 크기가 되는 순간 화면이 찌그러짐 | 10.1 |
| 3 | 엔티티 생성·삭제가 코드에만 있음 | 런타임에 오브젝트를 놓거나 지울 수 없음 | 10.2 |
| 4 | Inspector가 편집만 가능 | Component 추가/삭제 불가 (ROADMAP 요구사항) | 10.2 |
| 5 | 엔티티에 이름이 없음 | 목록이 "Mesh #3" — 씬이 커지면 구분 불가 | 10.2 |
| 6 | 에셋 로드가 `BuildWorld` 하드코딩 | 새 모델 하나 보려면 재빌드 | 10.3 |
| 7 | 마우스가 UI만 조작 | 뷰포트 클릭으로 월드에 배치할 수 없음 | 10.4 |
| 8 | 씬 구성이 코드 = 휘발성 | 에디터로 만든 씬을 저장할 방법이 없음 | 10.5 |
| 9 | `kMaxObjects = 32` 고정 | 에디터로 배치하면 금방 초과 → 예외 | 10.2 |

**건드리지 않는 것** (이번 단계 범위 밖):
- Undo/Redo — 에디터의 정석이지만 커맨드 패턴 도입이 필요한 별개 주제. Phase 12 후보
- 이동/회전 기즈모(3D 핸들) — ImGuizmo 같은 서드파티 영역. Inspector 숫자 편집으로 충분히 시작
- 멀티 셀렉션, 프리팹, 플레이 모드(에디터↔게임 전환) — 게임 로직이 생긴 뒤의 이야기
- 에셋 언로드 + 핸들 세대(generation) — 로드만 하는 동안은 불필요. 씬 전환으로 메모리가 아까워지는 순간이 트리거

## 2. 진행 원칙

Phase 9와 동일하다.

1. **한 단계 = 완결된 커밋 1~2개.** 각 단계가 끝날 때마다 빌드·실행·화면 확인.
2. **경계를 지킨다.** Renderer는 계속 ECS를 모른다. 에디터 UI(`Game/`)와
   렌더러 기능(`Graphics/`)이 섞이지 않는다 — 9.6의 ImGuiLayer/DebugUI 분리가 본보기.
3. **씬 데이터와 에디터 상태를 구분한다.** "무엇이 씬에 있나"는 컴포넌트,
   "지금 무엇을 선택했나"는 에디터 전용 상태. 저장 대상은 전자뿐.
4. 순서는 의존성 순이다: 뷰포트(10.1) 없이는 배치(10.4)가 무의미하고,
   배치 없이는 저장(10.5)할 씬이 코드 생성물뿐이다.

## 3. 단계 개요

| 단계 | 상태 | 주제 | 핵심 학습 | 규모(예상) | 태그 |
|------|------|------|-----------|-----------|------|
| 10.1 | 대기 | 오프스크린 렌더 타겟 + Scene Viewport | 렌더 투 텍스처, RT 수명 관리 | 대 | - |
| 10.2 | 대기 | 엔티티 편집 (생성·삭제·이름·컴포넌트) | 에디터 상태 vs 씬 데이터 | 중 | - |
| 10.3 | 대기 | 에셋 브라우저 | 디렉터리 스캔, 지연 로드 | 소 | - |
| 10.4 | 대기 | 뷰포트 배치 (픽킹) | 스크린→월드 언프로젝션, 레이-평면 교차 | 중 | - |
| 10.5 | 대기 | 씬 저장/불러오기 | 직렬화, 핸들을 어떻게 저장하나 | 중 | v1.1 |

트리거 대기 (ROADMAP 참조): 멀티 머티리얼 Submesh, 씬 계층 구조.
단계 번호를 주지 않는다 — 조건이 발생하면 그 시점의 단계에 끼워 넣는다.

## 4. 단계별 상세

### 10.1 오프스크린 렌더 타겟 + Scene Viewport

**목표**: 씬을 백버퍼가 아니라 우리가 만든 텍스처에 그리고, 그 텍스처를
`ImGui::Image`로 Scene Viewport 창 안에 표시한다. **Phase 11 그림자 매핑이
같은 기술(렌더 투 텍스처)을 쓰므로, 여기서 배우는 것이 그대로 이월된다.**

**작업 항목**
- [ ] `RenderTarget` 클래스: 색상 텍스처(RTV+SRV 겸용) + 깊이 텍스처(DSV) + 크기
- [ ] Renderer에 "화면에 그리기" 대신 "이 RT에 그리기" 경로 추가.
      백버퍼에는 ImGui만 그린다 (씬은 뷰포트 창 안에만 존재)
- [ ] Scene Viewport 패널: `ImGui::Image(rt.SRV, 패널크기)`. 창 크기가 곧 해상도
- [ ] 뷰포트 크기 변경 시 RT 재생성 (지연 처리 — 아래 함정 참조)
- [ ] 종횡비를 스왑체인이 아니라 **RT 크기**에서 얻도록 투영 행렬 수정
- [ ] 카메라 입력 게이트 변경: `WantCaptureMouse` 전역 차단 대신
      "뷰포트 창이 호버/포커스일 때만 카메라 조작"

**설계 결정**
- RT 포맷은 스왑체인과 동일(R8G8B8A8_UNORM). 포맷이 갈리면 PSO가 갈라진다
- 색상 텍스처 플래그: `ALLOW_RENDER_TARGET`, 상태 전이는
  `RENDER_TARGET ↔ PIXEL_SHADER_RESOURCE` — Phase 5 텍스처 업로드에서 배운
  배리어의 세 번째 용례
- RTV/DSV 슬롯은 9.3 할당자에서 받는다. RTV 힙이 SwapChain 소유(용량 2)라
  Renderer에도 RTV 할당자가 필요해짐 — 이 시점에 SwapChain 것과 통합할지
  별도로 둘지 결정 (권장: 별도. 수명이 다르다)

**함정**
- **GPU가 읽는 중인 RT를 재생성하면 안 된다.** 뷰포트 크기는 ImGui 프레임
  도중에 확정되는데, 그 프레임의 커맨드는 아직 옛 RT를 참조한다. 크기 변경은
  플래그만 세우고 **다음 프레임 시작(fence 확인 후)에** 재생성 — Window 리사이즈를
  지연 처리했던 것과 같은 패턴
- 뷰포트 크기가 0이 되는 순간(창 접힘)이 있다 — 0×0 RT 생성은 실패한다
- ImGui가 SRV를 `ImTextureID`로 받는다. 9.6에서 폰트가 쓰는 것과 같은
  셰이더 가시 힙 슬롯이어야 한다
- 씬을 백버퍼에 안 그리게 되면 **백버퍼 클리어 색이 곧 "에디터 배경"**이다.
  어두운 회색 정도로 바꿔야 도킹 빈 공간이 어색하지 않다

**완료 기준**: 씬이 도킹 가능한 Viewport 창 안에서 렌더링되고, 창을
늘리고 줄여도 찌그러지지 않으며(종횡비 = 창 비율), 다른 패널이 씬을
가리지 않는다.

### 10.2 엔티티 편집 — 생성·삭제·이름·컴포넌트

**목표**: 씬을 코드 없이 편집하는 데 필요한 나머지 절반. 9.6 Inspector가
"값 편집"까지 했으니, 이제 "구조 편집"(엔티티/컴포넌트 단위 추가·삭제)을 더한다.

**작업 항목**
- [ ] `Name` 컴포넌트 (문자열 하나). 목록 표시가 "Mesh #3" → "Crate_01"로
- [ ] 엔티티 생성(빈 엔티티 + Transform 기본 장착) / 삭제 / 복제 버튼
- [ ] Inspector에 "Add Component" — 컴포넌트 타입 목록에서 골라 장착
- [ ] Inspector 각 섹션에 제거 버튼 (X)
- [ ] `kMaxObjects` 상향 또는 동적화 — Object CB를 엔티티 수에 맞춰 재할당
- [ ] 삭제된 엔티티를 선택 중이었다면 선택 해제 (세대 검사가 이미 있으니
      `IsAlive` 확인만 추가 — 9.5에서 만든 generation이 여기서 첫 실전)

**설계 결정**
- Add Component 목록은 **수동 등록**으로 시작한다 (컴포넌트 7종을 나열하는
  switch 하나). 리플렉션/자동 등록은 타입이 수십 개일 때의 문제다
- 복제는 컴포넌트 단위 복사. Material 안의 핸들은 값 복사로 충분하다
  (핸들은 공유 참조라는 게 9.4 설계의 이득)

**함정**
- 엔티티 삭제는 **프레임 끝에 모아서**. ForEach 순회 도중 Destroy를 부르면
  swap-and-pop이 순회 중인 배열을 흔든다 — 삭제 큐에 넣고 순회 밖에서 처리
- Object CB 재할당은 GPU가 옛 버퍼를 읽는 중일 수 있다 — RT 재생성과 같은
  지연 패턴, 또는 "충분히 크게 한 번" (권장: 256으로 상향 후, 진짜 동적화는
  필요해질 때)

**완료 기준**: 마우스만으로 엔티티를 만들고, 이름 짓고, MeshRenderer를
붙여 화면에 등장시키고, 지울 수 있다.

### 10.3 에셋 브라우저

**목표**: `Assets/` 폴더의 내용을 에디터에서 보고 고른다. 하드코딩된
`BuildWorld`가 "초기 씬"에서 "예시 씬 중 하나"로 강등되는 시작점.

**작업 항목**
- [ ] `Assets/` 스캔: `.obj` → 메시 목록, `.png` → 텍스처 목록
- [ ] Asset Browser 패널: 두 목록 표시, 클릭으로 "현재 선택 에셋" 지정
- [ ] 선택 정보 표시 (파일 크기, 로드 여부. 메시면 로드 후 정점/삼각형 수)
- [ ] 로드는 **선택 시점에** ResourceManager로 (지연 로드 — 시작할 때
      폴더 전체를 로드하지 않는다)
- [ ] 미리보기: 텍스처는 SRV가 이미 있으니 `ImGui::Image`로 즉시 가능.
      메시 3D 썸네일은 **범위 밖** (RT가 또 필요한 일 — 트리거 대기)

**설계 결정**
- 디렉터리 스캔은 `std::filesystem::directory_iterator`. 파일 감시(핫 리로드)는
  아직 안 한다 — 새로고침 버튼이면 충분
- ResourceManager는 수정 없이 그대로 쓴다. 브라우저는 "경로 목록을 보여주고
  선택되면 Load를 부르는" UI일 뿐 — 9.4 캐시 덕에 중복 선택이 공짜

**함정**
- OBJ 로드는 수십 ms가 걸릴 수 있다(laevat.obj는 Debug에서 6초였다).
  선택 즉시 로드하면 UI가 멈춘다 — 일단 수용하고 기록만. 비동기 로드는
  스레드가 필요한 별개 주제 (Phase 12 Job System의 트리거 후보)

**완료 기준**: Assets/에 파일을 넣고 새로고침하면 목록에 나타나고,
선택하면 정보가 표시된다. 재빌드 없이.

### 10.4 뷰포트 배치 (픽킹)

**목표**: 브라우저에서 고른 에셋을 뷰포트 클릭 지점의 바닥 위에 놓는다.
스크린 좌표 → 월드 레이 변환은 이후 모든 마우스 상호작용(선택, 기즈모)의 기초다.

**작업 항목**
- [ ] 뷰포트 내부 마우스 좌표 계산 (ImGui 창 위치·패딩 보정 → 0~1 정규화)
- [ ] 언프로젝션: NDC → 뷰 공간 → 월드 공간 레이 (투영·뷰 행렬의 역)
- [ ] 레이-평면 교차: 바닥(y=0)과의 교점 = 배치 위치
- [ ] 배치 모드: 에셋 선택 상태에서 뷰포트 클릭 → 그 자리에 Entity 생성
      (Name + Transform + MeshRenderer, 텍스처는 브라우저에서 선택된 것)
- [ ] 클릭 픽킹(이미 있는 엔티티 선택)은 **바운딩 없는 지금은 보류** —
      레이-AABB 교차는 바운딩 박스 도입과 함께 (트리거: 뷰포트에서 직접
      선택하고 싶어지는 순간, 사실상 곧)

**설계 결정**
- 언프로젝션은 `XMMatrixInverse(view * proj)` 한 번이면 된다. DirectXMath의
  `XMVector3Unproject`를 써도 되지만, 행렬을 직접 뒤집어 보는 쪽이 학습 목적에
  맞다 — 뷰 행렬이 "카메라 변환의 역"이라던 Phase 6 개념의 복습
- 배치 높이는 바닥 고정(y=0 평면). 메시 바운딩을 모르니 절반 파묻힐 수
  있다 — 바운딩 박스(위 픽킹과 같은 트리거)가 생기면 바닥 위에 정확히 얹는다

**함정**
- 마우스 좌표는 **스왑체인이 아니라 뷰포트 RT 기준**으로 정규화해야 한다.
  10.1에서 종횡비를 RT로 옮긴 것과 같은 이유 — 이걸 놓치면 클릭 지점과
  배치 지점이 어긋나고, 창을 리사이즈할수록 더 어긋난다
- ImGui 창 안이라 `WantCaptureMouse`가 항상 true다 — "뷰포트 이미지 위"인지는
  `ImGui::IsItemHovered()`로 따로 판단해야 한다

**완료 기준**: 브라우저에서 메시를 고르고 뷰포트의 바닥을 클릭하면 그
지점에 엔티티가 생긴다. 창 크기를 바꿔도 클릭 지점이 정확하다.

### 10.5 씬 저장 / 불러오기

**목표**: 에디터로 만든 씬이 프로그램 종료를 살아남는다. v1.1 마감.

**작업 항목**
- [ ] 씬 파일 포맷 설계 (아래 결정 참조) — `Assets/Scenes/*.scene`
- [ ] 저장: World를 순회하며 엔티티별 컴포넌트 직렬화
- [ ] 불러오기: 파일 파싱 → World 재구성. **핸들이 아니라 경로를 저장**한다는
      게 핵심 — MeshHandle 3번은 다음 실행에서 아무 의미가 없다.
      저장은 `"Sphere.obj"`, 로드는 ResourceManager가 경로 → 새 핸들
- [ ] 절차적 메시(#cube 등)는 이름 그대로 저장하고, 로드 시 이름을 보고
      `AddMesh(Make...)`로 재생성
- [ ] File 메뉴: New / Open / Save / Save As (ImGui 메인 메뉴바)
- [ ] `BuildWorld`를 "기본 씬 생성"으로 유지하되, 시작 시 마지막 씬을
      열지는 선택 사항

**설계 결정**
- **자체 텍스트 포맷 (권장)**, JSON 라이브러리 벤더링 대신. 이유:
  씬 구조가 단순하고(엔티티 목록 × 고정 컴포넌트 7종), 직렬화를 손으로
  한 번 써봐야 "버전 필드는 왜 필요한가, 부동소수점은 어떻게 저장하나" 같은
  문제를 직접 만난다. 사람이 읽고 diff할 수 있는 줄 단위 포맷:
  ```
  scene 1            # 버전
  entity "Crate_01"
    transform 3.0 1.0 -4.0  0 0 0  1 1 1
    meshrenderer mesh="Crate.obj" texture="Crate.png" shininess=64 ...
  ```
  글자 그대로가 아니라 방향 제시다. 구현 시 확정한다
- 첫 줄에 **버전 번호**. 포맷이 바뀌는 순간(반드시 온다) 옛 파일을 구분할
  유일한 수단
- float은 `%.9g`로 저장 — 왕복(저장→로드) 시 비트 손실 없는 최소 자릿수
- 에디터 상태(선택, 카메라 위치)는 저장하지 않는다… 카메라는 예외로
  저장하면 편하다 — 씬 데이터가 아니라 별도 섹션으로

**함정**
- 파싱 실패 처리: 깨진 파일을 열다 절반만 로드되면 World가 오염된다 —
  **임시 World에 로드 후 성공하면 교체**, 실패하면 기존 씬 유지 + 에러 표시
- 한글 파일명/경로 — 파일 IO는 `std::filesystem::path`(wchar) 경유 유지.
  포맷 내부 문자열은 UTF-8로 통일
- 저장 순서: unordered_map 순회는 실행마다 순서가 다르다 → 같은 씬을 두 번
  저장하면 diff가 난다. 엔티티 인덱스 순으로 정렬해서 저장

**완료 기준**: ROADMAP 완료 기준 그대로 — 배치·편집한 씬을 저장하고,
프로그램을 재시작해 불러왔을 때 동일하게 복원된다. **여기서 `v1.1` 태그.**
